# prototype.md 结构规范

`prototype.md` 是原型目录里**给机器读**的那一半。arch-spec 靠它定 API 契约，arch-frontend 靠它定组件树。

它必须比 HTML 更精确：HTML 表达"看起来怎样"，这份清单表达"字段叫什么、值域是什么、什么时候为空、点了会发生什么"。凡是有歧义的地方，最终都会变成契约里的返工。

**下面是推荐结构，不是硬模板。** 章节编号、表的列、小节的取舍都可以按本次需求调整——过程比格式重要。真正不能少的是三类信息：**页面清单**（画了哪些页、对应哪条用户故事）、**字段清单**（每个字段叫什么、什么类型、值域是什么）、**状态清单**（正常之外还有哪些状态）。缺了这三样，arch-spec 就没法从清单推导契约。

## 为什么清单先行

先写清单会强迫你把字段、枚举、状态想全。反过来先画 HTML，容易画着画着漏掉某个状态，最后清单只能将就 HTML——而 arch-spec 读到的是将就后的清单。

```markdown
## 2. 字段清单

### 2.1 手势列表

| 字段名 | 显示名 | 类型 | 枚举值域 | 宽度 | 可排序 | 说明 |

### 2.2 手势表单

| 字段名 | 显示名 | 控件 | 类型 | 枚举值域 | 必填 | 默认值 | 校验规则 | 编辑时可否修改 |
|--------|--------|------|------|----------|------|--------|----------|----------------|
| `name` | 名称 | Input | string | — | 是 | 空 | 1-50 字，同组织内不重名 | 是 |
| `handSide` | 手侧 | Select | enum | `Left`=左手, `Right`=右手 | 是 | 空 | — | 否（创建后锁定） |

## 3. 状态清单

每个页面都要列全，缺一态就是缺一个实现分支。

| 页面 | 状态 | 触发条件 | 展示 |
|------|------|----------|------|
| 手势列表 | loading | 首次请求中 | 骨架屏（表格 5 行） |
| 手势列表 | empty | 请求成功且 0 条 | Empty + 「暂无手势，点击新建」 |
| 手势列表 | error | 请求失败 | 错误提示 + 重试按钮 |
| 手势列表 | 无权限 | 无 `gesture:list` | 不渲染本页面（路由级拦截） |
| 手势列表 | 边界-超长名称 | `name` > 20 字 | 单行省略 + Tooltip |
| 手势列表 | 边界-操作折叠 | 可见操作 > 3 个 | 前 3 个直出，其余收进「更多」 |
| 手势列表 | 边界-大数据量 | 1000+ 条 | 分页，每页 20 |
| 手势表单 | 校验失败 | 提交时字段非法 | 字段下方红字，首个错误自动聚焦 |
| 手势表单 | 提交中 | 请求进行中 | 确定按钮 loading 且禁用 |
| 手势表单 | 提交失败 | 后端返回错误 | toast 错误信息，弹窗不关闭 |

**必列的边界态**：超长文本、标签溢出、0 条、大数据量、无权限、网络失败。

## 4. 交互流程

描述页面间的跳转与弹窗开合，用文字流程图表达：

```

  ├─ [编辑] → 手势表单（带入行数据，手侧/末端类型禁用）

  └─ [删除] → Popconfirm → 确认 → 提交 → 成功 toast → 刷新列表

## T2 档位的裁剪

T2 只画改动区域，清单相应裁剪：

- §1 页面清单：只列受影响的页面
- §2 字段清单：只列**新增或变更**的字段，用 `新增` / `修改` / `删除` 标注
- §3 状态清单：只列受影响的页面
- §4~§7：照常

裁剪不等于省略——T2 的新增字段同样要列全枚举和校验，因为 arch-spec 要靠它加契约字段。

## 写作要点

**字段名用业务语义，不预设物理设计。** 写 `handSide`，不写 `hand_side`（那是数据库列名），也不写「手侧」（那是显示名）。arch-spec 拿到语义名去推导契约。

**枚举必须给完整值域 + 显示文本。** 只写「手侧是枚举」没有用——arch-spec 不知道有几个值，前端不知道渲染什么文案。格式：`Left`=左手, `Right`=右手。

**状态清单是最容易偷懒的地方，也是最容易出事的地方。** 只画正常态的原型，实现时必然漏掉空态和错误态，然后被测试打回来。六态齐全（正常/空/加载/错误/无权限/边界）是硬要求。

**设计决策要写理由，不只写结论。** 写「操作列收「更多」」没价值，写「收「更多」，因为与 `useTableToolbar` 的 `maxBar=3` 一致」才有价值——评审者据此判断你的选择是否符合项目约定。
