# 三轴执行细节

## 派发

有宿主通用子 agent 工具时，每轴创建独立任务，可并行；单轴执行者只做该轴。无派发能力时按 Correctness → Standards → Spec 串行执行，并说明没有上下文隔离。

## 统一评审对象

派发前确定目标项目的绝对路径、基线 commit、diff 命令、未跟踪文件清单和需求来源。各轴必须审查同一份代码；评审期间暂停该范围的实现修改。若代码变化，标记受影响结论并重新核对，不能把不同版本报告拼成一次完整评审。

相互独立的轴可以并行。不要让它们写入同一报告或共享有冲突的测试输出；主 Agent 汇总最终报告。

## 自包含任务说明

每个任务传入工作目录、统一评审对象、指定轴、检查方法和返回要求。从已加载技能的位置解析资源绝对路径；子 agent 无法读取时附必要方法。

| 轴 | 必需材料与方法 | 结果要求 |
|---|---|---|
| Correctness | diff、周边代码、调用方、本技能 Correctness 检查清单 | 每项给出可验证触发路径；没有触发路径不报 bug |
| Standards | diff、项目规范文件、工具配置、本技能 Standards 检查清单与 smell 基线 | 区分硬性违规与判断项，引用规则或 smell 名称和代码 |
| Spec | diff、真实需求文档、本技能 Spec 检查清单 | 引用需求原句，区分缺失/部分实现、范围外改动和实现疑点 |

给出报告长度预算与逐项格式：严重度、位置、证据、影响、建议。返回必须说明完成/部分完成/失败、实际检查范围、未验证项和阻塞。只报告，不修复代码。

## 汇总与降级

主 Agent 等待实际结果再汇总。中断、失败、无输出不能计为通过，必要时重派缺失轴或明确标注未完成。每轴独立列数量和最严重项，不合并成一个总判断，也不依据其他轴的结论改变本轴判据。

找不到 spec 时跳过 Spec 轴，写明“无 spec 可用，本次只完成两轴”。不从实现倒推需求、不发明验收标准；commit message 只有确实表达需求时才能作为需求来源。

串行执行时记录当前轴后再做下一轴。

## 边界

复杂度/覆盖率交给 `complexity-audit`，测试有效性交给 `mutation-testing`，实施与集成交给 `implementation-workflow`。本技能只负责三轴评审。
