# 三轴执行细节

## 派发

有宿主通用子 agent 工具时，每轴创建独立任务，可并行；单轴执行者只做该轴。无派发能力时按 Correctness → Standards → Spec 串行执行，并说明没有上下文隔离。

**并行不是默认动作。** 三轴会把 diff、周边代码和仓库规范各读一遍，token 成本约 3 倍，省下的只是墙上时间；小改动上派发是负收益。

### 结构判据决定要不要并行

跨仓库稳定的是**结构**，不是规模。命中任一条即派发：

| 结构判据 | 为什么并行有收益 |
|---|---|
| 改动跨越 ≥ 3 个顶层目录或独立包（扁平仓库按一级子目录/包计） | 三轴要读的材料天然分歧 |
| 改了公共接口，或被多处引用的符号 | Correctness 必须追调用方，该轴明显重于其余两轴，长尾能重叠 |
| 三轴需要读的材料来源互不相同（调用方代码 / 需求文档 / 规范文件） | 三者无共享读集，串行只是把重复劳动排成队列 |

### 规模只用来否掉假信号

**不设绝对阈值**——同一组行数/文件数在不同仓库里含义完全不同（文档仓库的 p90 可能不到 900 行，应用仓库的日常量级就是几千行）。只用它判断"是不是明显很小"：

```bash
BASE=$(git merge-base <固定点> HEAD)
git diff --numstat "$BASE"      # 本次逐文件改动
git diff -w --numstat "$BASE"   # -w 忽略纯空白，滤掉格式化 churn
git log -20 --no-merges --shortstat --pretty=format: \
  | awk '/files? changed/{ins=0;del=0; for(i=1;i<=NF;i++){if($i~/insertion/)ins=$(i-1); if($i~/deletion/)del=$(i-1)}; print ins+del}' \
  | sort -n | awk '{a[NR]=$1} END{ if(NR==0) print 0; else if(NR%2) print a[(NR+1)/2]; else print int((a[NR/2]+a[NR/2+1])/2) }'
```

只有**结构判据已命中、且"单文件 + 有效改动小于该中位数的一半"**时，才用规模否掉派发——例如跨了三个模块却只改一个常量或一句文案。**规模永远不作为触发条件**：改得多不等于三轴材料分歧大，一次全仓格式化可以改两万行而评审价值接近零。

**规模一律指有效改动**：先排除路径移动、生成物、lockfile、快照和纯格式化 churn。未跟踪的新文件不在 `git diff` 里，须用 `wc -l` 单独计入。近 20 个 commit 里样本不足（仓库历史太短）时跳过规模判据。

### 轴数不足也串行

有实质材料的轴 < 2 时串行：找不到 spec 时 Spec 轴本就要跳过（见「汇总与降级」），此时只剩 Correctness 一轴，派发纯属浪费。

## 统一评审对象

派发前确定目标项目的绝对路径、基线 commit、diff 命令、未跟踪文件清单和需求来源。各轴必须审查同一份代码；评审期间暂停该范围的实现修改。若代码变化，标记受影响结论并重新核对，不能把不同版本报告拼成一次完整评审。

相互独立的轴可以并行。不要让它们写入同一报告或共享有冲突的测试输出；主 Agent 汇总最终报告。

## 自包含任务说明

每个任务传入工作目录、统一评审对象、指定轴、检查方法和返回要求。从已加载技能的位置解析资源绝对路径；子 agent 无法读取时附必要方法。

| 轴 | 必需材料与方法 | 结果要求 |
|---|---|---|
| Correctness | diff、周边代码、调用方、本技能 Correctness 检查清单 | 每项给出可验证触发路径；没有触发路径不报 bug |
| Standards | diff、项目规范文件、工具配置、本技能 Standards 检查清单与 smell 基线 | 区分硬性违规与判断项，引用规则或 smell 名称和代码 |
| Spec | diff、真实需求文档、本技能 Spec 检查清单 | 引用需求原句，区分缺失/部分实现、范围外改动和实现疑点 |

给出报告长度预算与逐项格式：严重度、位置、证据、影响、建议。返回必须说明完成/部分完成/失败、实际检查范围、未验证项和阻塞。只报告，不修复代码。

**写入即卸载**：单轴 finding 多到会挤爆主 Agent 上下文时，让该轴把完整 finding 写盘，只返回结论摘要、该轴最严重项、finding 计数和落盘路径；落盘位置按调用方指定或复用仓库既有报告目录，并在最终报告里给出路径和"该文件未被跟踪"的提示。主 Agent 汇总时按需读取对应小节，不要把三轴全文都拉回上下文。

## 汇总与降级

主 Agent 等待实际结果再汇总。中断、失败、无输出不能计为通过，必要时重派缺失轴或明确标注未完成。每轴独立列数量和最严重项，不合并成一个总判断，也不依据其他轴的结论改变本轴判据。

找不到 spec 时跳过 Spec 轴，写明“无 spec 可用，本次只完成两轴”。不从实现倒推需求、不发明验收标准；commit message 只有确实表达需求时才能作为需求来源。

串行执行时记录当前轴后再做下一轴。

## 边界

复杂度/覆盖率交给 `complexity-audit`，测试有效性交给 `mutation-testing`，实施与集成交给 `implementation-workflow`。本技能只负责三轴评审。
