# Correctness 轴：bug 检查清单

## 目标

找出**真实的缺陷**，并用**触发路径**证明它是真实的。

**不是**找风格问题、不是找"可以更好"的写法、不是找测试覆盖率不足。那些属于别的轴或别的工具。

## 核心纪律：没有触发路径就不报

这条轴最容易失败的方式是"扫一遍 diff，凭感觉报一堆可能有问题的地方"。

**每条 Correctness finding 必须能说清：**

```text
什么输入 / 什么时序 / 什么状态  →  导致什么错误行为
```

说不出这条链的，就是猜测，**不要报**。

正确示例：

```text
`src/auth/session.ts:142` —— 刷新 token 与登出并发时，登出先清空 session，
刷新回调仍写入新 token，留下已登出的会话可用。
触发：登出请求与 token 刷新在同一秒内并发。
```

这不是合格 finding：

```text
`src/auth/session.ts:142` —— 这里可能有并发问题。
```

## 检查清单

按类逐项对照 diff。**只报 diff 引入或触及的**——不要评审历史遗留代码。

### 1. 空值与未定义

- 可能为 `null` / `undefined` / 空集合的返回值被直接解引用
- 可选链只加了一半（`a?.b.c` 中的 `c` 仍会抛）
- 数组 / map 查找后未检查是否命中
- 参数解构未给默认值

### 2. 边界与off-by-one

- `<` 与 `<=`、`>` 与 `>=` 的边界
- 空集合、单元素、超长集合
- 分页的首页 / 末页 / 越界页
- 字符串按字节 vs 按字符（多字节、emoji、组合字符）
- 时间边界：闰日、夏令时、时区

### 3. 错误处理

- **被吞掉的异常**：`catch {}` 或 `catch(e) {}` 里什么都不做
- 错误被捕获后**只打日志、不向上传播**，调用方以为成功
- 失败路径没有回滚已做的部分改动
- 资源未释放（文件句柄、连接、锁）——尤其在异常路径上

### 4. 并发与时序

- 读-改-写之间存在竞态
- 异步操作的结果覆盖了更新的状态（丢失更新）
- 缺少 await 导致顺序错乱
- 共享可变状态在并发路径上被修改
- 锁的获取顺序不一致导致死锁

### 5. 资源与生命周期

- 循环内重复创建昂贵资源
- 连接 / 流 / 监听器没有关闭路径
- 订阅没有对应的取消订阅
- 缓存无上限或无失效

### 6. 数据完整性

- 事务边界划错（该原子的操作被拆开）
- 部分成功未处理（批量写入中第 N 个失败）
- 唯一性 / 外键约束在前置检查中被忽略
- 类型转换的精度丢失（大整数、浮点金额）
- 序列化 / 反序列化的往返不一致

### 7. 安全（仅限 diff 引入的）

- 未参数化的 SQL / 命令拼接
- 路径遍历（用户输入拼进文件路径）
- 未转义的输出
- 敏感信息写入日志或错误消息
- 权限检查缺失或位置错误（在副作用之后才检查）

**不做**全面的安全审计——那是专门工具的事。这里只抓 diff 明确引入的。

### 8. 契约破坏

- 公共 API 的签名、返回结构、错误码被改变
- 向后兼容性被破坏但未标记为破坏性变更
- 调用方未同步更新

## 误报控制

### 先确认工具已经抓了什么

在报之前，看项目有哪些静态检查（类型检查、linter、构建）。**工具已经能抓的一律不报。**

判断方法：看 `package.json` scripts、`tsconfig.json` 的 strict 设置、lint 配置、CI 配置。

### 确认代码路径是活的

如果某个函数在 diff 中被修改，但**没有任何调用方**，报它的 bug 价值很低。除非任务是特意实现这个函数，否则先不提。

### 区分"真 bug"与"可疑风格"

- 真 bug：可以构造出出错的输入或时序
- 可疑风格：说不上哪里会错，只是"感觉不保险"

**只报前者。**

### 不确定就降级描述

如果直觉觉得有问题但构造不出触发路径，可以写成**待确认项**放在轴的末尾，明确标注"未能构造触发路径"。

这样既不丢线索，也不把它伪装成确定结论。

## 严重度参考

如果调用方要求分级，用这个基准：

| 级别 | 判据 |
|---|---|
| **高** | 会导致数据损坏、安全漏洞、生产故障，或静默的错误结果 |
| **中** | 特定输入 / 时序下出错，可复现但影响有限 |
| **低** | 边缘场景，影响小，修不修都不影响正常使用 |

**不要为了显得有价值而抬高严重度。**

## 与其他轴的边界

| 问题类型 | 归属 |
|---|---|
| 逻辑错误、边界、并发、资源、安全 | **Correctness 轴**（本文件） |
| 命名、重复、结构、抽象层次 | Standards 轴 |
| 需求缺失、范围蔓延 | Spec 轴 |
| 复杂度指标、覆盖率 | 不属于本技能 |
| 测试是否真正验证逻辑 | 不属于本技能 |
