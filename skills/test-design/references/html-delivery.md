# HTML 测试设计

默认交付自包含的 `test-design.html`，不是在对话贴 HTML 代码，也不强制附一份重复 Markdown。内容参考结构使用 Markdown 不影响正式格式。

首屏概括测试范围、规则依据、优先风险、开放问题及验证限制。提供稳定目录锚点；规则、用例和覆盖关系用可相互跳转的编号。简单用例用短表格，复杂场景用可展开卡片，避免十几列宽表。关键预期、禁止副作用及高优先级缺口默认可见，次要证据和长步骤可展开，完整内容仍保留在正文中。

“已设计／静态对应”与“实际执行”分开显示，不把颜色、勾选或完成比例当成测试通过。没有代码或架构材料时仍交付业务用例，把技术入口、fixture 或自动化承接限制标为未知，不新增固定前置文档或技能要求。

使用 UTF-8、语义 HTML、内联样式及系统字体，不依赖远端脚本／字体。核心内容在真实标题、section、列表和表格中，关闭 JS 仍可阅读，agent 可直接读取。可选筛选／搜索只是阅读增强，不删掉未匹配内容的权威记录，不改变设计或执行状态。

提供适合桌面、窄屏与打印的布局，宽表格只在自身区域滚动，打印能展开必要详情。有浏览器时检查实际阅读与打印效果；无浏览器时静态核对结构、链接、规则覆盖和内容完整性，明确视觉未验证。文档自检不运行目标系统测试或分析工具。

优先用户及项目约定位置；交付文件链接、关键缺口和实际检查范围。更新当前正本，用户明确要求其他格式时兼容，不自动启动任何后续流程。
