# HTML 设计文档

正式默认产物是面向人阅读、同时可供 agent 交接的 `spec.html`。内容参考和技能本身仍可使用 Markdown，不代表业务产物需要再生成一份 Markdown。

## 分层阅读

首屏概括目标、设计准备状态、用户已决定／待决定的关键问题、主要取舍与实施阻塞；提供章节导航。方案比较使用可横向对照的表格或卡片，同时展示推荐理由和缺点，不能用视觉强调把推荐伪装成用户已选。

整体边界与关键流程先于专项细节。架构、流程、ER 等图在对应章节直接可见，图源作为可展开的补充。模块、契约、数据、风险与验收通过稳定锚点相互引用；详细字段、DDL／伪代码、证据和图源可折叠，关键决策与阻塞默认展开。保持完整设计信息，不以界面精简为由删去错误语义或边界条件。

总体与少量专项优先单文件；内容确实很大时用 `spec.html` 导航到如 `backend-design.html` 的专题，标明统一基线并使用有效相对链接。子 agent 负责专题时遵循主 Agent 指定格式，主 Agent 完成统一入口、状态、样式与链接核对。

## 可维护与离线

默认使用 UTF-8、语义 HTML、内联 CSS 和系统字体，不依赖 CDN 或远端字体／脚本。核心正文、表格和静态图形直接在文件中，JS 仅增强阅读；内容可选择、搜索、复制，agent 可按标题和 `section id` 读取。配置与代码示例转义后放在 `pre/code` 中。

图形格式、图源和未完成／未验证状态按 `diagrams.md` 处理，页面中直接展示图形，不能用装饰方框代替真实关系。

不需要额外维护隐藏 JSON 或 Markdown 作为另一套正本；已有 OpenAPI／Schema 等专业契约继续作为其权威来源，HTML 链接并解释对应设计。局部阅读交互不代表用户批准决策，不用“已选中”按钮状态冒充授权。

## 验证与交接

在可用浏览器或渲染工具中查看实际产物，检查图形可读、目录与专题链接有效、宽表格／代码只在自身容器滚动、桌面及窄屏无整页水平溢出，检查打印布局及必要折叠内容能展开打印。没有工具时静态核对并说明视觉未验证。

交付实际文件链接、关键决定、准备状态及未验证项，不在对话粘贴长篇正文替代文件。其他阅读者或工具可直接读 HTML 的语义正文、表格、锚点和契约来源，不要求人为再转 Markdown，也不指定后续使用方式。

更新时修改当前 HTML 正本；若使用生成器，则修改其源并重建，明确源／产物关系，避免手工同步两套正文。用户指定其他格式或项目有既有正本约定时沿用，明确哪份内容有效。
