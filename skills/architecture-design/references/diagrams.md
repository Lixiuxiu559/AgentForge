# 图示选择与核对

图用于回答设计问题，与正文、契约使用同一组名称和语义。整体方案先画边界及关键关系，再随深化修订；按任务选图，不把所有图堆成固定套件。

## 选择图型

| 图型 | 何时使用 | 应表达什么 |
|---|---|---|
| 系统架构图 | 整体方案默认使用；小改动可画受影响边界 | 用户／客户端、内部模块、外部依赖、存储及调用方向；注明现状与拟议变更 |
| 流程图 | 涉及业务行为、决策或失败分支 | 起点、动作、判断、成功／失败／取消与恢复路径 |
| ER 图 | 涉及持久化实体、关系或数据模型变更 | 实体、关键标识、关系、基数与可选性；明确概念／逻辑／物理层次 |
| 时序图 | 多参与方调用、事务交界或异步流程 | 参与方、消息顺序、同步／异步、关键失败与重试；关联数据提交时机 |
| 状态图 | 状态转换及触发条件决定行为 | 状态、合法转换、触发条件及终态；与流程和契约枚举一致 |
| 部署图 | 部署拓扑、环境或信任边界发生变化 | 部署单元、网络／信任边界、依赖、入口及恢复边界；不把逻辑模块误画成独立服务 |

用户指定图型时交付；如业务确实没有实体关系等适用内容，明确说明原因并给合适表达，不虚构数据库来凑 ER 图。有实体但物理设计未定时交付概念／逻辑 ER，未知关系标注，不捏造主外键。

## 图源与展示

HTML 方案中直接展示可见图形，并将可编辑 Mermaid 等图源放入可展开区域或本地图源文件；常用 Mermaid 类型为 `flowchart`、`sequenceDiagram`、`erDiagram`、`stateDiagram-v2`。已有离线渲染器时生成内联 SVG 或本地图片；没有渲染器时可按同一关系绘制内联 SVG 并核对语义。不能只放一段依赖 CDN 才能渲染的 Mermaid 代码。架构与部署可用带边界分组的 flowchart，图中注明逻辑还是部署视图；沿用项目已有格式或用户明确要求的其他格式。

用户要可演示／交互／导出的精细图时，可使用实际可用的绘图工具或技能增强展示，同时保留可维护图源和语义说明；不把某个额外插件作为本技能的硬依赖。现有工具不支持某图型时使用支持它的格式，不静默丢失实体基数或交互语义。

已有渲染器时检查语法并查看实际渲染，核对文字可读、连线与标签无歧义、主要阅读顺序清楚。无法生成某张图形时仍保留图源并注明图示尚未完成；已有 SVG 但无浏览器时说明视觉未验证。两者不能混称，也不为普通设计自动安装整套绘图环境。

## 语义检查

- 节点用稳定标识，显示名与正文一致；箭头标明动作／协议／数据或关系，不用装饰线代替语义。
- 拆开复杂视图，避免一张图同时塞入业务流程、部署拓扑和全部字段；各图通过同名模块和实体相互关联。
- ER 核对一对一／一对多／多对多及零／一的可选性；多对多需要物理建模时明确关联实体，逻辑关系不代表已存在数据库外键。
- 流程／时序核对关键失败分支、持久化时机、重试是否可能重复副作用；状态转换与 API／事件描述相容。
- 图示中的现状、提议、未知项可区分，必要时说明依据；不从未经确认的运行环境推导实际部署图。

修改方案、契约或数据关系后，同步受影响图源、渲染产物与引用；渲染成功只证明可绘制，不能代替设计正确性核对。
