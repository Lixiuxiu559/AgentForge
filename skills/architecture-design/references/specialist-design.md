# 按需深化

仅阅读与当前任务相关的部分。深化以已确认方向、整体边界和共享契约为依据；没有另一端的独立任务仍可直接设计。相关设计应完整到实施者能落实既定规则，不将关键选择留给实施阶段，不重写总体方案或生成生产代码。

## 前端

- 从原型或明确页面需求映射页面／路由、布局与组件职责；优先复用真实组件与设计系统，区分新增与已有部分。
- 区分服务端状态、全局／局部 UI 状态、表单与 URL 状态；写清权威来源、更新和同步方式。
- 将用户操作对应到契约，说明加载、空、错误、权限、校验、提交中、重试／取消等适用状态。前端隐藏操作不等于服务端授权。
- 涉及异步请求、分页、缓存或实时更新时，考虑竞态、失效、断线恢复与重复触发；按真实需要设计，不机械引入状态库或 WebSocket。
- 渲染、拆包、可访问性、多端与国际化只覆盖相关约束；性能预算基于目标设备、网络与项目基线，不复制固定指标。
- 给出涉及区域、兼容／迁移影响、保持不变项及与原型对应的验证办法；不输出完整组件、hook 或样式实现。

## 后端与数据

- 定义服务／模块职责、调用关系与现有代码落点，明确校验、权限和业务不变量的执行位置；不预设微服务、缓存或消息队列。
- 接口实现方案遵循共享契约；说明事务、并发更新、幂等和错误映射，防止只有端点清单却没有行为语义。
- 数据设计覆盖实体与基数、唯一性、空值、关联完整性、访问模式与索引理由；区分逻辑模型和目标数据库物理设计。
- 涉及实际建表或数据修改时，明确所需字段类型、约束、索引、事务和权威写入方，引用已有定义或补足设计；缺少关键 Schema／版本依据时标明受阻范围，不把示例当完整契约。
- 如涉及 Schema 演进，说明旧数据处理、约束建立时机、兼容读写、迁移顺序、锁／大表影响、验证及回退／补偿；需要精确 DDL 时基于明确数据库版本和已核实 Schema 给出设计草案，缺少依据不伪造可执行 SQL。
- 异步处理写清生产者、消费者、投递与重试、重复处理、顺序及失败恢复；缓存写清权威数据源、失效和陈旧容忍度。
- 针对实际风险说明日志、指标与排障线索，估算注明输入和依据；交付变更范围、保持不变项及验收入口。

## 部署、集成及其他专项

- 安全与运行风险按实际涉及的数据和边界深化，参照 `quality-validation.md`，不以是否修改部署作为安全分析的前提。
- 只有任务涉及部署变更才深化环境、部署单元、外部依赖、信任边界、配置／凭据机制、切换与恢复；设计不等于执行部署。
- 多客户端或第三方集成检查协议、权限、限流、超时、兼容及失败传播，不只检查 Web 前端。
- 大型迁移或跨模块重构可单列演进阶段、兼容窗口、集成验证和可逆边界；文件划分按真实责任而非固定前后端目录。

## 返回主 Agent

返回设计结论、依据、模块／文件影响、适用图示、验收办法、假设与风险，以及对共享契约的建议修改和受影响方。涉及新重大取舍时返回候选、优缺点与推荐，由主 Agent 组织用户决策；指出无法满足的约束或未完成范围，不静默修改整体基线。
