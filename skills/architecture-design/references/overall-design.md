# 整体方案要点

按任务裁剪以下信息，不将每一项机械扩展为必需章节。小改动可合并成短方案；复杂任务先交代全局，再引用专题深化。

## 问题与证据

- 目标、范围、用户可观察的结果及明确不处理项。
- PRD／对话要求、原型、现有代码／测试、契约、ADR 与项目规范的来源。
- 已确认约束、现状与目标的差异、设计假设、开放问题及其阻塞范围。
- 会决定架构的关键质量场景、优先级及用户决定，按 `quality-validation.md` 核对；跨模块决策不能留给实施阶段重新选择。

## 边界与关键路径

说明参与者、信任边界、模块职责、外部系统、数据与控制流。标注复用／新增／变更／移除；模块不等同部署服务，不因画了多个方框就拆成微服务。

选本次关键业务流程，包含入口、条件、成功结果和重要失败／取消路径。涉及状态机时明确状态、合法转换、触发者和副作用；不要仅画成功路径。

## 数据与共享契约

先定义领域语义、实体关系、数据所有者与生命周期，再完成本次实施所需的物理设计。已有 Schema 可引用；依据不足时明确受阻部分，不能只给概念 ER 就称数据库设计已完成。ER 图区分概念／逻辑／物理层次，不能把逻辑关系直接当作已部署外键。

按适用性描述：

| 边界 | 设计信息 |
|---|---|
| 调用接口 | 方法／调用方式、输入输出、字段类型／值域／空值、错误与权限、分页／排序（如适用） |
| 事件或任务 | 生产者／消费者、触发时机、载荷、顺序、重复／失败处理、恢复办法 |
| 数据修改 | 权威写入方、校验、事务边界、并发控制、一致性要求 |
| 兼容性 | 现有消费者、旧数据／旧客户端、增删改策略及过渡步骤 |
| 页面支撑 | 原型字段与行为由接口、派生计算或本地状态中的哪一项满足 |

共享契约集中定义一份，专项设计引用并补充实现责任，避免各写一套可漂移的定义。已有 OpenAPI、Schema 或类型定义可作为真源，方案链接并说明变更，不强制复制。

## 决策与取舍

关键取舍与决策记录按 `decisions.md`；性能／容量目标、估算和实测按 `quality-validation.md`，不复制模板数字。

仅关键且需长期追踪的决策按项目约定记录 ADR；保留状态和替代关系，不要求每个功能新增 ADR。

## 承接实施

说明工作项与模块边界、前置依赖、可并行部分、集成点及受保护范围。涉及数据或接口演进时说明兼容阶段、迁移验证、切换与回退／补偿条件，不能统一假定“先执行全部 SQL 再上线”。

将关键业务结果、契约、失败恢复与质量目标关联到验收办法和项目实际验证入口。设计阶段尚未运行的测试写为待实施验证，不把命令清单当作测试已通过。

最终按 `handoff.md` 完成实施准备检查与统一交接摘要；总体初稿中的建议、待决定事项与最终设计不能混用同一状态。
