# 设计委派与集成

## 派发条件

主 Agent 在用户已确认或授权选择的方向内形成整体基线，明确模块、数据归属、共享契约与关键依赖，再拆分依赖该方向的深化任务。方向未定时可以派发候选调查／验证，但不能将某候选当作确定路线让各端开工。按独立设计问题拆任务，例如前端状态流、后端事务与数据迁移；没有前端的任务不强拆前端，有多个后端模块也不必合并成一个任务。

边界稳定且相互独立的设计可并行。依赖未确定的字段、业务规则或关键技术选择时先解决依赖；若任务只是调查候选，应明确返回调查结果而非既定方案。隔离上下文不会隔离文件系统，主 Agent 独占总体方案／共享契约，子任务只写各自明确的专题文件，或仅在回复中返回设计。

## 自包含任务说明

派发时提供：

- 目标项目绝对路径、相关代码基线及可读取材料；不得假设子 agent 继承主对话。
- 本次设计目标、范围、已确定业务规则和必须遵守的约束。
- 用户已选择的方案、授权边界及待决定事项；与本任务相关的质量场景、关键假设及需要提供的验证证据。
- 整体方案与共享契约的位置、内容摘要和基线标识；未落盘时直接传入所需内容，不为派发强制保存到项目。
- 本技能与适用 reference 的绝对路径，或在不可读取时传入必要方法。
- 本任务需回答的问题、图示要求、预期产物、允许写入位置、禁止操作和前置依赖。
- 专题需落盘时使用主 Agent 规定的 HTML 文件和章节锚点，保留可读正文与可见图形；若只返回设计内容，由主 Agent 统一编入 HTML，不擅自增加重复 Markdown 正本。
- 返回格式：完成／部分完成／失败；设计结论与证据；验收办法；假设与开放问题；契约变更建议及影响范围。

声明任务只做限定设计，不编码、不执行迁移／部署，不递归启动整个编排。实际调用宿主提供的通用子 agent 工具，不指定虚构角色类型、固定模型或权限白名单。

## 共享契约变更

子 agent 发现整体方案不足时提出问题、证据、备选修改及受影响方；不直接覆盖共享文件。主 Agent 核对必要性与兼容性，涉及用户关键取舍时先完成下述讨论，再更新基线并通知所有受影响任务：已有结果也需要重新对齐。不要用“未发现两端互相反对”代替契约正确性检查。

涉及用户约束、业务规则或重大取舍变化时，按 `decisions.md` 组织方案比较后请用户决定；已确认方向内的普通设计细节在范围内处理。子 agent 只能推荐，不能代替用户作最终选择。所有未解决差异明确归位，不因某角色资历高而自动采纳其建议。

## 集成验收

等待实际结果，检查任务是否完成、引用是否支持结论、设计是否覆盖指定问题。主 Agent 核对跨模块字段、状态、权限、错误、事务／事件语义，更新整体正文与图示；不同专项的术语和实体关系必须一致。

失败／中断任务可在同一范围内重试或由主 Agent 接手；无法补齐的说明缺口与阻塞范围，不无限重派。保留真实执行记录：是否使用独立上下文、哪些任务串行／并行、关键差异如何解决；无需暴露全部内部对话。
