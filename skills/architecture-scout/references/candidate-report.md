- 目标模块 / 主题：

- 调查方式：主 Agent / 1 个 researcher / N 个并行 researcher

## 调查结论

允许结论为：**暂未发现值得优先实施的架构改造。**
如果有候选，按 Strong → Worth exploring 排序；Speculative 单独放在待调查区。

## 推荐顺序

只在有候选时写：

1. <候选> —— <为什么现在值得关注>

不要跨候选写“总体最重要”的模糊判断；推荐顺序必须说明时间敏感性和证据强度。

## 下一步

报告完成后停止，询问用户：

```text
你想深入哪一个候选？也可以选择暂不改造。
```

用户选择后再进入详细设计；不要在本报告中直接创建接口或修改代码。
