# HTML PRD 交付

目标是让人容易理解需求，同时保留架构与实施所需的完整依据。正式默认交付 HTML 文件，Markdown 参考结构仅用于检查信息完整性。

## 阅读结构

首屏放功能名称、简短目标、范围摘要、事实／草案状态与关键待确认项；长文提供章节导航和稳定锚点。正文按需用需求卡片、业务流程、规则表及验收对照呈现，控制行宽、字号、留白和对比度，不把每段都装进卡片。

范围、关键规则、验收条件及阻塞问题默认可见。术语解释和次要依据可折叠，但完整内容仍在文件中；不为缩短页面删减规则或异常分支。规则和验收使用可引用的标识／锚点，便于原型及架构链接到具体条目。

## 文件与可读性

使用语义 HTML：`header`、`nav`、`main`、带标题和唯一 `id` 的 `section`，规则与验收使用真实列表或表格，避免整篇依赖 JS 生成。内容应可选择、搜索、复制，agent 可直接读取 HTML 正文和结构，不需要额外 Markdown 副本或隐藏的另一套正本。

默认单文件、UTF-8、系统字体、内联样式；不依赖 CDN、在线字体或远端脚本。必要脚本只增强目录、折叠等阅读功能，关闭脚本仍能读取核心内容。外部来源可保留链接，但离线阅读不能依赖下载它们。转义正文／代码中的特殊字符，避免格式处理吞掉需求内容。

适配常见桌面和窄屏，宽表格只在自身容器横向滚动，正文不产生整页水平溢出。提供打印样式，打印时展开必要细节、避免遮挡；不靠隐藏正文解决布局问题。流程图如有，直接提供可见图形与文字说明，不只展示图源。

## 检查与交付

有浏览器／渲染工具时打开实际 HTML，检查桌面与窄屏下的导航、锚点、表格、折叠和打印可读性；与需求核对内容未丢失。没有工具时至少静态核对结构、链接及正文完整性，并明确视觉未验证。

交付链接及摘要。后续变更直接更新这份 HTML；生成工具有独立源时说明源与构建关系，不手工维护两套不同内容。用户明确要求 Markdown 或既有正本为其他格式时遵循其要求，说明哪个版本是当前依据。
