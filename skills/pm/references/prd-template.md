# PRD 参考结构

这是一份可裁剪的检查表，不是固定格式协议。必需的是信息，不是章节名；简单需求可以合并章节或省略不适用部分。保留的章节应写清内容，不保留空表、“待补充”或占位符。

## 必需信息

### 问题与目标

- 谁或什么使用方遇到什么问题。
- 期望达成什么结果。
- 为什么现在做（有依据时说明）。

### 范围与边界

- 本期包含什么。
- 明确不包含什么。
- 与已有行为的关系。

### 需求行为与业务规则

- 适用角色与条件。
- 触发操作。
- 正常结果。
- 关键异常、禁止行为或边界情况。
- 涉及权限、状态流转、数据概念、兼容性或非功能要求时，写明业务层要求；不涉及时不保留空表。

### 验收标准

- 前置条件。
- 操作或输入。
- 可观察结果。
- 对应的需求或规则。

可以使用 Given/When/Then，也可以使用清晰的分条列表；重点是能判断通过或失败，并覆盖关键规则与异常。

## 按需添加

- **用户故事**：本期要做时列出；优先级只表示本期内的排序，不表示是否纳入本期。
- **业务流程或状态流转**：存在多步骤、分支或状态变化时使用。
- **影响与依赖**：改变已有行为或依赖其他团队、系统时说明。
- **成功指标**：有可信数据或明确衡量办法时补充，不编造指标。
- **风险与取舍**：存在真实范围竞争或风险时说明。
- **术语表、概念模型、流程图**：复杂概念需要时使用。
- **假设与开放问题**：存在推断或未知项时必须列出，标明影响和待确认方。

## 编写检查

- 每项关键规则能对应到验收条件。
- 范围、用户故事和验收标准互相一致。
- 事实、决定、假设和未知项分开表达。
- 没有未解释的占位符或互相矛盾的章节。
- 不写技术实现、代码结构或物理数据设计；用户已确定的约束标明来源。

## 不包含

- 固定保存位置、目录结构或文件命名。
- 作者、版本、日期等项目管理字段（项目另有要求时除外）。
- 强制 RICE/ROI 打分、固定角色名单或统一成功指标。
- 后续流程命令或其他技能的调度说明。
