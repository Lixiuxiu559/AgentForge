# 行为验收场景

在隔离副本运行，保留输入、实际输出和文档 diff。脚本测试只能验证确定性行为；以下场景需要让 Agent 实际执行后判断，未执行不能称为通过。

| 场景及请求 | 主要验收点 |
|---|---|
| Java/React 项目已有模块 Wiki，要求解释一个业务流程 | 沿用入口与项目术语，只读取相关范围；回答有来源，不因没有统一配置重建知识库 |
| Java/React 项目删除带注解类、重命名中文路径，要求同步待提交变更 | 比较索引而非最终工作区，旧路径仍参与关联；检查反向引用，无法映射项不遗漏 |
| AgentForge 这类技能仓库，要求初始化知识 | 围绕技能发现、资源、宿主边界组织；不创造订单、角色权限或 Java Controller 章节 |
| 小型 CLI/库没有 Wiki，要求记录参数与退出码 | 从真实契约、帮助和实现取证；可交付一篇小文档，不强制四文件布局或额外服务 |
| 当前代码与已批准契约不一致，要求“同步 Wiki” | 标出冲突及依据；不自动把实现缺陷改写成规范 |
| 代码已有新行为，但没有部署证据 | 记录实现基线；上线状态保持未知，不以合并或测试通过替代部署事实 |
| 人工新增解释后，重复执行同一维护请求 | 保留人工内容；证据无变化时无无意义 diff，不刷新未核验条目的日期 |
| 写到一半中断，用户继续期间修改了文档 | 重新读取当前内容与 diff，补全剩余工作，不按过期上下文覆盖新修改 |
| 只有部分源码可读，关键需求缺失 | 交付范围明确的观察与开放问题，不编造业务规则，不声称完成全库核验 |
| 只要求检查链接，工具报告部分语法未覆盖 | 保留 partial 和具体缺口，不自动改文档，不宣称业务语义通过 |
| 插件安装目录与目标项目不同 | 脚本仍检查显式目标根，输出和知识不会写入插件目录 |
| 无既有约定的小型 CLI 要求建立 Wiki | 使用 small 模板生成单页知识和项目自有配置；填入真实来源或明确未知，显式传配置完成结构检查，不复制所有模板 |
| 多模块项目只需模块概览，部分模块另有复杂规则 | 使用 modular 骨架并维护入口导航；按需拆分规则、映射和依赖，不强制每个模块四文件 |
| 已有英文手册且项目指定了必需章节 | 保留原路径与标题，按 project 配置检查指定章节，不要求中文默认元数据；后续检查继续显式使用项目配置 |

同步评估时同时构造“已暂存改动被未暂存改动抵消”的情况：暂存区检查仍应发现待提交变化。纯工作区、分支范围、未跟踪、删除及重命名各有明确范围，不能用一种比较替代所有请求。
