# 行为验收场景

在隔离副本运行，保留输入、实际输出和文档 diff。脚本测试只能验证确定性行为；以下场景需要让 Agent 实际执行后判断，未执行不能称为通过。

| 场景及请求 | 主要验收点 |
|---|---|
| Java/React 项目已有模块 Wiki，要求解释一个业务流程 | 沿用入口与项目术语，只读取相关范围；回答有来源，不因没有统一配置重建知识库 |
| Java/React 项目删除带注解类、重命名中文路径，要求同步待提交变更 | 比较索引而非最终工作区，旧路径仍参与关联；检查反向引用，无法映射项不遗漏 |
| AgentForge 这类技能仓库，要求初始化知识 | 围绕技能发现、资源、宿主边界组织；不创造订单、角色权限或 Java Controller 章节 |
| 小型 CLI/库没有 Wiki，要求记录参数与退出码 | 从真实契约、帮助和实现取证；可交付一篇小文档，不强制四文件布局或额外服务 |
| 当前代码与已批准契约不一致，要求“同步 Wiki” | 标出冲突及依据；不自动把实现缺陷改写成规范 |
| 代码已有新行为，但没有部署证据 | 记录实现基线；上线状态保持未知，不以合并或测试通过替代部署事实 |
| 人工新增解释后，重复执行同一维护请求 | 保留人工内容；证据无变化时无无意义 diff，不刷新未核验条目的日期 |
| 写到一半中断，用户继续期间修改了文档 | 重新读取当前内容与 diff，补全剩余工作，不按过期上下文覆盖新修改 |
| 只有部分源码可读，关键需求缺失 | 交付范围明确的观察与开放问题，不编造业务规则，不声称完成全库核验 |
| 只要求检查链接，工具报告部分语法未覆盖 | 保留 partial 和具体缺口，不自动改文档，不宣称业务语义通过 |
| 插件安装目录与目标项目不同 | 脚本仍检查显式目标根，输出和知识不会写入插件目录 |
| 无既有约定的小型 CLI 要求建立 Wiki | 使用 small 模板生成单页知识和项目自有配置；填入真实来源或明确未知，显式传配置完成结构检查，不复制所有模板 |
| 多模块项目只需模块概览，部分模块另有复杂规则 | 使用 modular 骨架并维护入口导航；按需拆分规则、映射和依赖，不强制每个模块四文件 |
| 已有英文手册且项目指定了必需章节 | 保留原路径与标题，按 project 配置检查指定章节，不要求中文默认元数据；后续检查继续显式使用项目配置 |
| 业务项目没有正式 PRD，用户明确要求生成 Wiki | 实际生成可用内容；代码行为归为实现观察，未明确的目标行为局部标记，不先要求补审批制度或只交付治理建议 |
| 代码常量与注释不同，项目没有新的决策材料 | 核对调用路径及有效来源，解释查证范围；仍无法判断的预期保留冲突，不把代码常量写成已批准规则 |
| 已有 dev 执行记录但没有 prod 版本证据 | 分开标注预期、实现和 dev 运行观察；不声称 prod 生效，也不将生产核验变成普通文档生成的前置条件 |
| 排位赛与娱乐赛共同使用轮换目录，前端也存在共享包 | 根据独立规则及生命周期决定合并或拆分，来源多对多；用 mapping 报告核查重叠并解释原因，不以目录名直接决定模块或盲目扩大映射 |
| 用户要求持续同步，只有初始模块配置 | 交付真实首份复核记录、触发约定与验证结果，或明确未完成范围；不能仅称记录机制可选便宣告同步初始化完成 |
| 用户只要求一次性项目说明 | 完成说明和适用检查，明确维护机制的实际状态，不自动修改 CI、创建发布记录系统或要求新增部署权限 |
| 用户要求全项目知识，规模需要分批处理 | 在入口记录完整覆盖清单和进度，持续完成所要求范围，不把首批少量模块称为全项目已完成 |

| 项目已有英文架构和发布手册，要求补全架构部署运维 Wiki | 保留路径与自定义章节，链接有效旧知识；覆盖清单交代已覆盖/未知/不适用，不重复搬迁 |
| 仓库含部署清单但无法访问环境 | 区分声明配置与实际状态，记录版本、时间、证据缺口；不把 CI 文件存在写成线上健康 |
| 技能或库项目没有自营服务、监控或数据库 | 记录宿主、安装分发、验证与恢复边界，不虚构生产集群或数据库备份，不自动执行安装发布 |

同步评估时同时构造“已暂存改动被未暂存改动抵消”的情况：暂存区检查仍应发现待提交变化。纯工作区、分支范围、未跟踪、删除及重命名各有明确范围，不能用一种比较替代所有请求。

## 待确认项分类的行为验收

用真实既有 Wiki 做增量维护，保留逐项去向与实际 diff，不只对模板措辞做匹配：

- 本地应用的多实例、无遥测、缺少未被要求的监控等已知范围归正文；未执行测试归核验范围，已确定未支持功能不变成待办。
- 未演练的恢复方案在操作旁仍有显著限制；若任务明确要求验收该恢复能力，保留影响操作的具体未决问题，不以“少写待确认项”为目标删风险。
- 合成一项已读来源仍冲突且影响当前操作的问题，确认它能保留依据、影响与查证办法；无符合项允许明确写无。
- 查找同项跨页重复、正文已确认但入口仍说未核实的矛盾；只修表达，不将历史观察改成新运行事实。
- 不自动部署、探查私有数据、补建监控或新增产品 backlog；相同材料再次维护应无无意义变更。

## 正文证据与映射的行为验收

- 实际启动参数只给 Dev 设置 cwd：环境页区分继承目录、数据目录与绝对数据库路径；不能猜测正式版 cwd 或把相对备份路径套用所有环境。
- 历史记录只读到一个平台更新清单：保留观察时间并限制到该平台声明，不扩展成全渠道同步或资产完整性。
- 某存储渠道清理旧版本：描述渠道保留策略，不推导其他渠道不可下载或旧数据一定可回退。
- 运维建议没有有效项目决策：标为建议/未演练，不标“约定”；必要风险仍可见。
- 知识页引用的版本、工作流、配置或失败分类未进本模块映射：补齐必要来源并解释共享原因。在隔离副本改来源后对应页须 stale，还原应恢复；不能靠其他模块状态代替。
- 入口、元数据、正文对同一观察的声明相反：按真实证据局部对齐，不刷新未执行核验的日期。check/freshness 通过不表述成机器证明正文正确。
