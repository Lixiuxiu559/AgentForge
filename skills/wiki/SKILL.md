# 项目开发知识

为开发人员和编码 Agent 讲清项目如何工作、如何修改。以代码、配置和工程脚本为主，解释用途、流程、条件、异常、依赖及修改影响；关键结论附来源文件，必要时定位符号。已有目录、术语、人工解释和检查约定优先。

Wiki新增文件和文件夹沿用项目现有文档的命名语言与风格，不根据本次对话语言自行翻译；`modules`、`README.md`、`reviews.json`、`wiki.config.json` 保留固定名称。已有路径不自动重命名，模板内部英文名称不决定输出文件名；命名与类型配置见 `references/templates.md`。

## 任务入口

Wiki 可由用户或 agent 作为独立任务调用，不限定调用者。按本次操作确定范围：阅读／检查保持只读，创建／维护／同步才修改相关内容。其他技能不调度 Wiki，也不在执行期间或收尾时夹带 Wiki 更新；参考已有文档不构成维护任务。

| 任务 | 按需读取 |
|---|---|
| 阅读或解释 | 项目知识入口；已配置时先按 `references/freshness.md` 检查相关模块，再核实关键来源 |
| 初始化 | `references/initialization.md` 确定覆盖与模块，`references/templates.md` 选择布局 |
| 维护或同步 | 读取相关正文和实际代码 diff，按下方流程更新；Git比较范围见 `references/tools.md` |
| 机械检查 | `references/tools.md`；新鲜度、复核声明与候选检查见 `references/freshness.md` |

## 编写与复审

1. **定范围**：读取项目指令、现有知识及相关未提交内容，确定要维护的模块和文件。实质性多模块任务在宿主可委派时按 `references/module-workflow.md` 分工编写与独立复审；运行中的子Agent合计最多3个，编写、复审及返工共用上限，由主Agent排队调度。小修正或无委派工具时自行完成，说明实际复核方式。
2. **读代码、写知识**：按 `references/content-verification.md` 追真实入口、调用方和配置覆盖，直接修正错误原句、表格或步骤。已有映射时可用 `mapping --document` 直接查看来源覆盖、缺口和歧义，命令见工具参考。
3. **复审与整合**：核对代码依据、遗漏条件、范围扩大及操作风险；按正文核对方法通读受影响整页，将新增内容融入合适章节，整理过时描述、重复内容及格式，统一跨模块概念与重复结论。读回最终正文和 diff，运行项目约定检查，仅为实际核对范围保存复核记录，交付文档、关键变化与必要技术缺口。

正文按当前实现编写，不等待PRD或产品批准；文档/注释不同则核实执行路径，必要时简注差异。测试代码不等于测试已通过，部署脚本不等于已上线。已知边界、未运行与建议在相关位置说明，待确认项只留查证后仍影响开发或本次操作的技术问题。

维护任务中完成范围内文档，不自动修复代码、部署、读取凭据或改造CI。机械通过不证明知识语义正确；技能不常驻监听，新鲜度触发取决于项目实际接入。行为评估见 `references/evaluation-cases.md`，日常任务无需逐项执行。
