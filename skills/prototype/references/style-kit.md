# 项目原型样式基础

同一项目的原型共用一份样式基础（下称 kit），避免每次重新推导样式基线导致取值漂移。新项目没有现有页面时，kit 记录的是设计建议。

## 位置与内容

优先项目约定；无约定时放在各需求文档目录的共同上级，如 `docs/prototype-kit/`，交付时说明位置。项目有多个应用或主题时按应用分别建立，不混用。

| 文件 | 内容 |
|---|---|
| `tokens.css` | 颜色、字体与字号层级、间距、控件尺寸、圆角、阴影、表格密度的 CSS 变量；每个变量注释来源（文件与变量／选择器，或截图区域）及性质（源码事实／视觉观察／估计／建议） |
| `shell.css` 与外壳片段 | 目标应用的侧栏、顶栏、内容区骨架 |
| `components.css` | 本项目常用控件的静态外观与状态，如按钮、输入框、选择器、表格、弹窗、抽屉、标签、分页 |
| `kit.md` | 适用应用、主题与视口，样式基线表（维度见清单说明的“样式基线与差异”），版本号与修订记录，离线替代与已知视觉差异 |

## 使用与维护

开始新原型时先查找 kit。有 kit 时复制到本原型目录的 `kit/` 作为快照，在 `prototype.md` 记录 kit 版本；原型目录因此保持自包含，也不会因 kit 后续修改而变化。清单只记录本次新增或偏离 kit 的规则。

没有 kit 时按主技能的样式基线步骤取证，结果写成 kit，而不只写进本次 `prototype.md`。

发现 kit 取值错误或缺失且有新证据时，修改 kit、升版本并记录原因。已交付的原型不追溯修改，除非用户要求。

## 取值规则

页面样式中的颜色、字号、间距、控件高度、圆角和阴影只引用 kit 变量。需要新值时，先在 `tokens.css` 增加变量并标为建议，再在页面中引用。只属于某个页面的布局尺寸（如某面板宽度）可以直接写，并注释依据。

缺少依据时从相邻同类组件推导并标为建议，不用组件库默认值填补：同一组件库不同大版本的主色、圆角和控件高度不同，默认值经常与项目定制不符。

交付前搜索页面文件中 kit 以外的颜色值（十六进制、`rgb()`）以及 `font-size`、`height`、`border-radius` 的 px 值，逐项改为变量或注明理由。

## 参照来源优先级

1. 目标页面的真实渲染：本地运行的应用、可访问的环境或用户提供的截图。
2. 目标应用源码中的样式定义：主题配置、全局样式、组件覆盖。
3. 同模块相邻页面的推导。
4. 用户提供的参考稿或旧原型。

用户明确要求以某份参考稿或新风格为准时，按用户指定处理并记录调整范围。来源冲突时取优先级高的值，在 `kit.md` 或 `prototype.md` 记录差异。

## 视觉对照

目标应用已在本地运行或有可访问的环境时，在相同视口和主题下截取参照页与原型对照；不为此自行安装依赖或启动生产应用。都没有时，交付前集中请用户提供一次参照截图，说明需要哪些页面和视口；用户无法提供时标为“视觉未对照”，不阻塞交付。

对照发现的问题按归属记录：kit 本身取值不对的修订 kit；本次原型偏离的修正原型并在清单记录。
