# 根因证据与调查复用

## 从症状反向追踪

1. 固定最外层失败：实际值与期望值、请求/实体标识、时间与环境。
2. 找到产生错误值或执行错误操作的直接位置，记录输入及前置状态。
3. 沿调用者、数据来源和状态写入点上溯，找出第一次违背约定的位置。
4. 构造可区分的观测：若候选原因成立，哪个输入、状态或分支必须出现什么变化？用正常路径作对照，优先排除其他同样合理的解释。
5. 用“触发条件 → 状态偏差 → 传播路径 → 用户症状”解释结果，附实验；找不到其中一环就注明未知，不能仅凭错误消息给出确定根因。

多组件问题按请求经过的边界逐段检查实际输入输出，不因为某服务最后报错就归责它。日志相关性或最近一次提交只用来选调查方向；因果结论需要触发路径与区分性证据。

## 假设与实验记录

| 假设 | 已有依据 | 区分性预测/实验 | 实际结果 | 当前判断 |
|---|---|---|---|---|
| 一个可否证的原因 | 路径、行号、日志或观测 | 怎样会支持或推翻它 | 已运行结果，或明确未运行 | 保留 / 排除 / 未定 |

候选数量由证据决定；不要为了凑数编造原因。实验应改变一个关键变量，保持其余条件尽量相同。隔离副本中的替换实验要记录改了什么，不能把临时替换当作用户工作区的正式修复。

## 定向插桩

先选择能直接看到状态的调试器或已有诊断工具，再考虑日志。探针必须回答具体问题，放在状态变化或危险操作之前/之后的相关边界，使用本次独有前缀以便定位清理。

按项目实际输出通道选择日志方式，并确认测试 runner 不会吞掉它；不要跨语言强制使用某个 logger 或 `console.error`。只记录必要字段，对命令、日志和报告脱敏；绝不把凭据或原值映射写入报告。

临时源码探针优先放在隔离副本；必须改动用户工作区时，先按主技能的诊断授权规则处理。撤销只针对本次改动，不使用覆盖整个文件的回滚。

## 使用 research 和调查子 agent

小问题在主上下文直接调查。需要隔离大量日志、梳理长调用链或确认外部版本行为时，使用可用的 `research` 方法及宿主通用子 agent；仅独立问题并行，不让多个 agent 写同一份源码或共享测试产物。宿主无委派能力时自行执行，无 `research` 时按本文件契约调查。

派发内容包含目标项目与技能资源绝对路径、症状、版本/环境、范围、已有证据索引、需要回答的具体问题，以及**当前仍在诊断、不得实施修复**。有临时实验权限时同时限定副本与允许的操作。资源不能读取时附必要方法，不假定目标项目内有 AgentForge 的 `skills/`。

返回以下信息：

- 完成 / 部分完成 / 受阻，以及调查范围和代码基线。
- 事实、假设、已排除项和置信度；证据为源码行号、日志位置或命令输出。
- 实际运行的命令、条件与结果；未运行项必须显式标出。
- 缺失证据、临时改动/产物位置、下一项最有价值的验证。

主 Agent 先读结论和证据索引，按 `research` 要求抽查少量关键证据，不重新读全部源码、日志或报告。关键证据较少时只核对实际存在的项，不为凑数量扩大调查。原始症状的验收由主 Agent 负责；已记录且基线未变化的诊断实验无需全部重跑。

仅对证据冲突、影响方案的重要缺口或已变化的版本补查；优先交回原调查者补证。多个 agent 赞同同一解释不能替代独立证据。最终回归验证是在修复后检查新状态，不能因复用调研而省略。
