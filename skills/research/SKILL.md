# 调研与调查工作流

## 目标与适用范围

将调查问题转化为有证据支持、可复核的结果。只负责调查取证与调查任务编排，交付调查结果。

需要追踪多个线索、验证不同解释或综合证据进行比较时使用；简单事实查询直接处理。用户明确指定时遵从，并按问题规模精简过程，不以文件数量或耗时决定调查规模。

## 调查问题与范围

明确要回答的问题、调查范围，以及相关的版本、时间和环境条件；遵循用户、项目或调用方的交付要求。

问题模糊时，先拆成可验证的问题，避免无目标泛搜。只确定与本次调查相关的条件，不要求所有调查都具备代码项目、分支或运行环境。

## 证据要求

根据调查问题，优先使用与目标版本、环境和时间范围一致的一手证据。区分规定行为与实际行为，不把当前实现直接当成正确需求，也不把文档说明直接当成运行事实。

关键结论通过独立来源或不同验证方式交叉核对；不同页面转述同一来源，不算独立证据。主动核对影响结论的反证和证据冲突，无法解决时保留不确定性，不只选取支持预想结论的材料。

证据应可定位，并能说明其适用条件；来源存在不等于支持结论。

## 调查任务委派

需要隔离大量材料或分配独立调查问题时，使用宿主的通用子 agent 能力；独立且无冲突的任务才并行，无派发能力时自行调查。

任务说明包含问题、范围、相关版本与条件、实际可用的项目或资料位置、必要的技能资源及交付要求。子 agent 只调查分配的问题，按本技能的结果要求返回，不代替主 Agent 决策。

主 Agent 等待实际结果，核对支撑关键结论的证据；发现缺失、冲突或版本不一致时补证。未完成或失败的调查不能算作已验证。

## 结果要求

直接回答调查问题，给出关键证据与结论；篇幅按问题规模调整，不强制套完整报告模板。结果应清楚区分：

- **事实**：直接观察或核实的内容，附可定位的来源及相关版本、时间或环境条件。
- **推断**：基于事实得出的解释，说明推理依据，不把假设写成已验证事实。
- **未确认项**：证据、权限或工具不足以确认的部分，以及影响结论的反证、证据冲突和适用限制。

说明关键结论的确定程度及依据，不强制使用统一的置信度标签。证据不足时允许交付未确定结论；“没有查到”不等于“不存在”，“工具不可用”不等于“系统没有数据”。
