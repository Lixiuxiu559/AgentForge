# 子任务卡模板

每个派发给 `implementer` 的子任务都使用以下格式。字段不可省略；无内容时写「无」。

````markdown
### 任务 <编号>：<清晰的任务名称>

**目标**

- 要完成什么，以及完成的判定是什么

**已确认的约束**

- 必须遵循的接口、数据模型、命名或错误处理约定
- 来自 spec / ADR / 用户确认的决策

**允许修改**

- src/feature/**
- tests/feature/**

**禁止修改**

- 其他并行任务负责的路径
- 公共配置与依赖清单（package.json / pom.xml / go.mod 等）
- 与本任务无关的模块

**前置依赖**

- 无
- 或：依赖任务 <编号> 已定义的 <接口 / 类型 / 文件>

**验收标准**

- 条件 1（可客观判断）
- 条件 2（可客观判断）

**验证命令**

```bash
<项目实际可运行的命令>
```

**返回格式**

- 修改了什么
- 修改了哪些文件
- 实际执行的验证命令与结果
- 是否存在未解决的问题
````

## 使用说明

### 目标必须可验收

```text
✅ 导出接口返回 PRD 约定的字段结构，空数据返回空数组而非 404
❌ 完善导出功能
```

### 约束必须来自已确认的决策

不要在任务卡里引入新的设计决策。若需要决策，先回到编排阶段与用户确认。

### 允许与禁止范围都要写

只写允许范围容易让子 agent 越界修改共享文件。禁止范围至少要包含：

- 其他并行任务的文件
- 依赖清单与锁文件
- 公共配置

### 验证命令必须是实际命令

写项目真实可执行的命令，不要写「运行相关测试」这类模糊描述。

### 返回格式保持统一

统一返回格式便于集成阶段快速核对，也便于发现子 agent 未实际执行验证的情况。
