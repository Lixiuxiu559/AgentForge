# 子任务卡模板

派发实施任务时填写以下字段；无内容写「无」。

````markdown
### 任务 <编号>：<清晰的任务名称>

**执行上下文**

- 目标项目的绝对工作目录与代码基线
- 项目指令、需求和必要资源的绝对路径
- 必要 Skill / reference 的绝对路径；无法读取时附必要方法
- 只执行本任务，不重启编排

**执行规则**

- 先阅读现有实现和项目指令，复用接口与风格，不猜测 API
- 只修改任务范围，不擅自改变公共接口或引入无关重构、依赖
- 补充必要测试，失败时修复；不删除或弱化测试，不伪造结果
- 普通实现细节自行判断，缺少关键条件时向主 Agent 回报阻塞

**目标**

- 要完成什么，以及完成的判定是什么

**已确认的约束**

- 必须遵循的接口、数据模型、命名或错误处理约定
- 来自 spec / ADR / 用户确认的决策
- 设计入口与基线、权威契约位置、用户方案选择／授权及本任务的可实施范围（有架构设计输入时）
- 不得自行改变的关键取舍；发现设计不成立或需改变共享契约时，携带证据报告主 Agent，不静默换方案

**允许修改**

- src/feature/**
- tests/feature/**

**禁止修改**

- 其他并行任务负责的路径
- 公共配置与依赖清单（package.json / pom.xml / go.mod 等）
- 与本任务无关的模块

**前置依赖**

- 无
- 或：依赖任务 <编号> 已定义的 <接口 / 类型 / 文件>

**验收标准**

- 条件 1（可客观判断）
- 条件 2（可客观判断）

**测试设计输入（本任务需要业务验证时）**

- 已确认的业务规则、用例编号或设计文档位置
- 前置条件、具体输入/操作、预期结果与副作用断言
- 项目已有测试入口、需补充或复用的用例、尚未确认的规则与验证限制
- 无现成测试设施时明确回报，不擅自安装框架；不因缺少设计而从实现反推预期结果

**验证命令**

```bash
<项目实际可运行的命令>
```

**返回格式**

- 状态：完成 / 部分完成 / 失败
- 修改了什么
- 修改了哪些文件
- 实际执行的验证命令与结果
- 用例与测试代码的对应关系，以及未实现或未执行的场景（如适用）
- 是否存在未解决的问题
````
