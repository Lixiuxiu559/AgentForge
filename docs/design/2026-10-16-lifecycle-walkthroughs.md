# 全生命周期工作流场景推演

状态：讨论稿；与 `2026-10-16-lifecycle-workflow.md` 配套。日期：2026-10-16。

方法：用假设任务按节点推演输入、动作、结果及失败处理，检查设计是否存在断点。以下项目、操作和结果均为示例，未真实编码、部署或执行模型行为评测。

## 1. 新功能：订单导出至测试环境

假设请求：“新增订单CSV导出，部署到测试环境供验收。”不包含生产部署授权。

| 节点 | 关键输入与动作 | 合格产物/交接 |
|---|---|---|
| N0 | 核对项目、Git状态、现有导出/权限、测试环境和发布入口 | 终点为测试环境验收；列明已有修改及能力 |
| N1 | 确认谁能导出、字段、时间范围、数据上限、敏感信息和失败反馈 | 需求R1权限、R2数据范围、R3CSV内容、R4异常处理；关键未决项不默填 |
| N2 | 依据数据规模决定同步/异步，明确接口、权限与数据保护、下载失败处理 | 选定设计、用例预期、风险和测试方法 |
| N3 | 先定接口，再按不冲突的任务划分实现；共享fixture有归属 | 任务依赖、资源所有权、集成及验收命令 |
| N4 | 实现与测试，检查真实接口及UI链路 | 候选代码、相关验证、集成结果 |
| N5 | 验证无权访问被拒、数据范围正确、特殊字符CSV可读、失败无额外泄露 | R1–R4对应证据、固定候选版本、必要检查结果 |
| N6 | 核对测试环境部署对象、构建、回滚及验收路径 | 测试环境发布安排；复用明确的部署授权，不自动扩大至生产 |
| N7 | 部署确定产物并核对实际版本 | 测试环境运行版本及部署记录 |
| N8 | 在测试环境完成关键路径与约定观察 | 测试环境交付完成；生产上线未执行 |

注入条件A：N4发现产品实际要导出全部历史数据，与N2同步方案不匹配。预期回N1核对规则，再N2评估异步与容量；受影响任务及测试待复核，其他独立任务不自动作废。

注入条件B：N5测试通过但构建时更新依赖。预期候选产物已变，复核依赖影响及必需检查；不能把旧测试结果直接绑定新产物。

检查结论：设计可解释入口、发布环境边界、需求变更回退和产物漂移。真实执行能力仍待验证。

## 2. 存量改动：订单查询接口增加可选筛选条件

假设项目已有接口契约和回归测试；请求要求向后兼容，完成PR验收，不包含部署。

1. N0读取现有契约、用户改动和授权范围。已有规格有效，不重新启动泛化访谈；终点记录为代码/PR验收。
2. N1只确认新增条件的缺省、组合及分页规则。N2只设计相关接口/索引/查询及兼容影响，保留原公共行为。
3. N3先确定契约及共享测试数据归属，再安排查询实现、调用方和测试。不能同时修改同一契约文件而假定可自动合并。
4. N4各任务局部通过后，主Agent验证端到端查询、分页和缺省行为。子任务“完成”只代表局部结果。
5. N5在固定基线核对需求、回归与性能要求；满足原交付终点后报告代码验收完成。N6–N8标记为本请求不适用，不宣称已经上线。

注入条件A：集成时发现某调用方依赖旧错误码。预期先核对契约：实现违反契约回N4；设计本来改变了公共行为则回N2并核对范围，而非临时吞掉错误。

注入条件B：三轴评审尚未完成，另一任务更新相同查询代码。预期标记受影响评审已失效，停止拼接不同版本结果；冻结或明确新的候选对象后补核对。

注入条件C：项目缺少性能验证设施，而需求明确要求响应时间不能退化。预期保留必需验证缺口，提出可执行的量测/人工交接；不能因为无工具删除该需求。

检查结论：支持中途复用、有限终点和变更影响传播；不能把每次有限交付都强迫推到部署。

## 3. 线上故障：请求超时与紧急缓解

假设请求：“排查线上超时，先给方案。”当前只授权诊断；存在有限日志，不能稳定复现。

1. N0明确诊断终点及可读范围，保留已有改动；读取现成日志与指标，不擅自生产插桩。
2. 调试流程收集观测与正常对照；区分“根因已验证、有支持、未确定”。无法复现不直接宣布不存在问题。
3. 证据支持但未证实第三方延迟时，交付假设与下一项取证方法；如建议暂时关闭受影响入口，将其作为缓解方案说明影响、恢复条件与验证。
4. 只有用户具体授权缓解及环境操作后，形成独立缓解工作项，精简通过N2/N3/N5/N6；执行授权内动作，并在N8检查错误与用户影响。
5. 缓解成功只记录“服务影响缓解”，根因修复工作项仍未完成。永久修复继续诊断→具体方案批准→N4/N5→发布与观察。

注入条件A：关闭开关命令超时。预期执行状态为未知，先读取开关与运行状态或查询操作标识；不盲目重试，不把超时直接认作失败或成功。

注入条件B：缓解期间发现必须执行数据清理。预期原开关授权不覆盖数据删除，停止该动作并说明具体方案；已授权独立的观察仍可继续。

注入条件C：灰度修复后错误率升高且满足已定恢复条件。预期执行授权内恢复、验证实际环境、记录本次发布未成功，再进入根因调查。回滚成功不计作新版本上线完成。

检查结论：诊断、缓解、永久修复及发布授权分开；同时避免重复询问已明确授权的局部动作。

## 4. 横向故障检查

| 条件 | 设计要求的处理 | 禁止的错误归因 |
|---|---|---|
| Agent在实施中中断 | 核对任务记录、实际diff、运行中的工具，恢复第一个未满足任务 | 旧记录写执行中就假定仍有进程 |
| Agent在迁移中中断 | 核对迁移记录、目标schema/数据及部署操作标识 | 未拿到成功输出就重跑有副作用操作 |
| 子任务失败/无报告 | 主Agent检查实际状态，回收或重新安排其范围 | 无输出视作通过 |
| 构建与突变共享输出 | 分离输出或串行，明确资源所有者 | 上下文独立就认为无冲突 |
| 审计提出无证据建议 | 补证或列建议，不升级为已证实缺陷 | 多个Agent重复同一猜测等同确认 |
| 缺少必需验证工具 | 解决设施或交接并保留缺口 | unavailable写成passed或不适用 |
| 用户接受剩余风险 | 记录授权、适用版本、范围及责任，保留原检查结果 | 风险接受改写测试结果 |
| 上线观察尚未结束 | 保持等待或明确交接责任方 | 没有继续看就声称持续观察正常 |
| 数据迁移不可直接逆转 | 预先选择备份恢复、前滚或分阶段方案 | git revert等于数据回滚 |
| 任务取消 | 根据用户决定记录取消，保留已有副作用及清理交接 | 取消自动代表环境已恢复 |
| 发布安排完整但生产授权未给出 | N6产物完成，顶层等待具体授权，N7待执行 | 把准备完成等同允许部署，或把授权缺失记为部署失败 |
| 用户在部署排队时撤回授权 | 不启动新部署；查询排队任务能否取消及实际状态 | 认为撤权会自动撤销CI或自动授权环境回退 |
| 启动迁移后、保存返回标识前中断 | 依靠预先记录的意图和目标状态核验；不足则交接 | 没有本地操作ID就推断迁移从未发生 |
| 两个会话准备修改同一环境 | 使用宿主已有互斥或指定单一操作者，不能保证时串行 | 在文档写“独占”就宣称已获得工具层锁 |

## 5. 从纸面推演到真实验证

上述推演只说明草案对这些条件给出了处理规则。尚未证明模型能遵守、宿主能执行、实际部署能恢复。

后续验证建议采用一个可控项目，分别记录：

- 正常新功能的需求→代码→产物→环境→关键用户路径证据链。
- 一次存量变更中需求/接口或代码基线改变后的失效传播。
- 一次部署结果未知或部分失败时的状态核验与恢复。
- 一次中断跨会话续接，不重复有副作用操作，也不跳过授权。
- 对照不同宿主时的实际工具能力与降级，不能用一个宿主的结果替代全部。

下一轮设计讨论优先确认：目标形态、节点是否需要调整、阶段授权及首次验证项目。确认后再拆技能及实施任务。

## 6. 本轮设计复核记录

复核对象：当前总体工作流及上述纸面场景。复核方式：按目标要求逐项检查契约，再用反例检查状态推进；未运行真实Agent或部署操作。

| 目标要求 | 对应设计 | 当前证据强度 |
|---|---|---|
| 需求到上线的阶段覆盖 | 主文N0–N8及路径表 | 设计已描述，未实施验证 |
| 节点职责、输入输出与准入退出 | 主文节点契约；推进前置检查 | 文本齐全，真实遵从未验证 |
| 交接与持久状态 | 最小逻辑记录、交接包、尝试与恢复 | 语义已定义，载体和读写机制待定 |
| 授权边界 | 主文职责与授权、撤回授权、推进规则 | 已覆盖典型边界，具体项目权限待定 |
| 失败回退与结果未知 | 三类场景及横向故障表 | 有纸面处理路径，不能证明恢复有效 |
| 暂停、恢复与审计 | 状态变化、输入版本、尝试历史和恢复顺序 | 设计已描述，需真实中断与复验 |
| 真实项目端到端闭环 | 第5节后续验证要求 | 未完成；未选项目、未实施或上线 |

本轮反例发现并修订了三处设计缺口：发布准备完成与部署授权混在同一出口；只有状态名称而缺少推进判据；结果未知时缺少执行前意图及尝试记录。补充后仍保留目标形态、状态载体、宿主及验证项目等待决策事项；没有将草案标为已批准。
