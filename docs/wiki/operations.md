## 日常检查与可观测性

本插件没有自营服务进程、数据库或专属指标/告警平台；仓库提供本地 CLI 输出和 GitHub Actions 日志，宿主执行日志由对应宿主管理。先记录插件版本、宿主、加载路径、目标项目、命令与实际错误，避免将安装目录当成被检查的业务项目。

只读检查入口为 node tools/doctor.mjs、npm run wiki:check、npm run wiki:mapping、npm run wiki:freshness；npm test 执行隔离回归。受影响知识应先查 freshness，再核对来源，保存 review 仅在真实复核完成后进行。CI 的日志路径和触发方式见 [环境说明](environments.md)，当前远端日志未查询。

## 故障处理

| 症状 | 先查什么 | 判断与后续动作 |
|---|---|---|
| 找不到技能或资源 | doctor、清单的技能路径、技能 frontmatter、宿主实际加载路径 | provider 本地回归通过仅覆盖隔离场景；真实宿主按原安装说明检查和刷新，不自动重装 |
| Wiki 报 broken-link / missing-section | check 输出中的具体路径、项目配置与实际章节 | 局部修复链接或补有依据内容；既有格式使用 requiredSections，不为全绿迁移目录 |
| Wiki stale / unknown / blocked | freshness 状态、来源 diff、旧复核原因 | 对照来源更新或记录 no-change；冲突未解决保留 blocked，不能只刷新记录 |
| mapping 存在未映射或共享路径 | 模块实际职责与源码、共享原因 | 报告只供路径分析；不要把全仓纳入所有模块清空报告 |
| gate 不通过 | 工作区/暂存区/提交范围是否一致，来源与记录是否都在候选中 | 按候选范围复核；工作区新记录不能替代旧提交，提交顺序见新鲜度说明 |
| Qoder 构建失败 | 四处版本、zip 是否可用、13 个技能及打包资源 | 根据具体错误修复源文件后重建，不手动改 ZIP 绕过检查 |
| Qoder 策略未转换或仍为旧版 | 是否安装生成 ZIP、客户端版本和实际资源路径 | 按 Qoder 安装说明重新导入/安装，重启或 reload 后核对；真实升级缓存未实测 |
| 发布准备失败 | 工作区是否干净、是否 main、doctor、版本与标签 | 本轮不运行 release；发布操作沿用既有发布约定与显式授权 |

以上是基于 CLI 和发布检查实现的排查路径，不是已重现过全部宿主故障。复杂问题保留完整非敏感输出和可复现条件，交由对应调试流程；不采集 Token 或私钥。

Qoder 本地构建入口为 npm run package:qoder；产物位于 dist/qoder（忽略构建目录）。CommonJS 脚本以 .cjs 扩展名避免受仓库或目标项目 ESM 配置影响；不编辑共享技能以适配单个宿主。安装与更新方式见[Qoder 说明](../qoder.md)。

## 备份与恢复

源码、知识和复核声明由 Git 历史追溯；未提交修改不受远端历史保护，执行重装、清理或版本切换前先保留所需本地改动及目标项目知识。插件未定义自身数据库，数据库备份对该插件不适用；用户目标项目数据和宿主配置的备份由对应项目流程负责，不能据此删除或忽略。

插件版本回退应沿用宿主已有安装/版本选择办法，核查安装标识和资源路径；本轮未演练真实宿主回退。不得移动已公开发布的远端标签，错误发布以新版本处理，详见发布约定。包回退不等于目标项目数据恢复，任何写入、发布或清理动作须满足实际授权；本页只提供维护知识。
