## 用途与边界

Wiki 内容保存在目标项目，技能资源随插件分发。Agent 负责取证、填充模板和增量维护；check、changes、mapping、freshness 和 gate 只读；review 仅显式保存复核声明，不调用外部模型、不生成业务事实。已有约定优先，无约定的新知识库才采用默认 small 或 modular 骨架。

| 意图 | 输出 |
|---|---|
| read | 按问题读取并给出依据与未知项 |
| init | 选择布局和模板，生成有来源的知识与检查配置 |
| maintain | 保留人工内容的局部更新 |
| check | 结构、路径、链接及覆盖限制 |
| sync | 指定 Git 范围的影响分析；按已授权范围建议或更新 |

## 主要流程

1. 读取项目入口和指令，明确目标根、范围及既有约定。
2. 无约定时选用所需模板，记录范围、状态、基线、来源和待确认项；不复制全部模板或猜测事实。
3. 将默认结构选择保存在项目配置；之后显式通过 --config 传入。
4. mapping 检查当前 Git 可见工作区的路径覆盖与共享来源，Agent 据源码判断边界；check 检查结构与链接，changes 按 Git 范围生成关联材料。
5. 引用前 freshness 检查来源和知识是否匹配已复核指纹；Agent 读取实际 diff、契约与 Wiki，区分文档过期、实现缺陷和未决规则。
6. 开发收尾实际核对后，用 review 保存 updated、no-change 或 blocked 的原因及证据。gate 按所选候选检查新鲜度与映射覆盖；合并前还需 check 检查结构。

当前 AgentForge 自用 Wiki 采用 modular，本模块单独拆出规则和代码映射；其余模块按需保持合并。

### 架构与运行知识

初始化逐项评估项目概览、业务/能力、架构、部署环境、运维排障；已有文档可链接复用，缺口或不适用说明原因。新增五类按需模板，通过 structure.documents.type 显式选型，不按路径强套旧文档。环境页检查环境、观察时间和证据来源字段，未知可明确记录；脚本不会证明上线健康或感知外部漂移。本仓库沿用外部架构/发布手册并新增环境与维护页作为实际应用。

### 交付与知识状态

预期与约定来自技能和 references：持续维护应有模块来源与维护说明；持续同步还须真实复核记录和触发约定；强制门还须对应接入证据。缺少 PRD 或部署证据时仍交付有依据的内容，未知只标注在相关条目，不自动扩展成审批或 CI 改造。重要结论区分预期、实现、运行验证及推断；页面“部分核验”和 semantic: not_run 都不能替代 Agent 的语义核对。

实现观察：mapping 不读取源码内容，报告不能自动决定模块划分；默认规则页已有独立分类章节，旧规则标题仍兼容并在 legacyDocuments 中显式列出。本仓库本轮按来源调整规则页，而非为通过结构检查强制迁移全部页面。

### 正文与来源的核对

重要结论按 content-verification 方法核对对象、环境、时间、实际生效链与证据效力，不把一个平台清单或某个分发渠道策略扩大为整体结论。操作路径区分工作目录、数据根和数据库位置，建议不标为已采用约定。维护时从正文反查来源进入该页所属模块的映射，不能用另一个模块的 stale 替代本页失效检查；入口、元数据、表格与正文同时对齐。脚本仍只检查结构、路径及指纹，正文语义由执行者实际核对。

### 待确认项的语义准入

待确认项只列合理查证后仍影响当前必要结论、决策或操作的问题，并交代影响、已有依据与下一步查证。已知边界、未执行验证、临时会话状态和未被要求的未来能力分别归位；没有符合项就明确写无。未演练恢复等风险仍保留在操作旁，不能为减少问题而删掉。模板保留章节，脚本不按关键词判断语义。
