## 用途与边界

Wiki 内容保存在目标项目，技能资源随插件分发。Agent 负责取证、填充模板和增量维护；check、changes、mapping、freshness 和 gate 只读；review 仅显式保存复核声明，不调用外部模型、不生成业务事实。已有约定优先，无约定的新知识库才采用默认 small 或 modular 骨架。

| 意图 | 输出 |
|---|---|
| read | 按问题读取并给出依据与未知项 |
| init | 选择布局和模板，生成有来源的知识与检查配置 |
| maintain | 保留人工内容的局部更新 |
| check | 结构、路径、链接及覆盖限制 |
| sync | 指定 Git 范围的影响分析；按已授权范围建议或更新 |

## 主要流程

1. 读取项目指令、现有入口及相关未提交内容，确定开发知识范围和模块职责。
2. 以当前代码、配置、调用关系与工程脚本解释架构、业务实现、部署和运维，关键结论附来源；产品资料不同不阻断代码描述。
3. 实质性多模块维护由模块编写者专注取证，再由独立上下文追源复审；主 Agent 整合导航、来源映射及跨模块关系，并统一排队调度。运行中的子Agent默认最多3个，编写/复审/返工共用名额，宿主更低上限优先；遇限流降并发，不叠加未停止的超时任务。小修正直接完成，无宿主委派能力时明确自行复核范围。这是技能的调度约定，由执行者落实，工具脚本不启动或限制宿主Agent。
4. mapping 检查路径覆盖，--document直接列本页覆盖/缺口/歧义；check检查结构与链接。工具不自动证明正文语义，也不代写知识。
5. 已接入项目在读取前检查freshness，收尾核对实际diff及相关知识，再保存实际范围的review；gate按所选候选及项目策略检查同步状态。

当前 AgentForge 自用 Wiki 采用 modular，本模块单独拆出规则和代码映射；其余模块按需保持合并。默认规则模板以“当前实现规则”“条件与边界”组织，旧两代规则章节继续兼容。

### 架构与运行知识

初始化逐项评估项目概览、业务/能力、架构、部署环境、运维排障；已有文档可链接复用，缺口或不适用说明原因。新增五类按需模板，通过 structure.documents.type 显式选型，不按路径强套旧文档。环境页检查环境、观察时间和证据来源字段，未知可明确记录；脚本不会证明上线健康或感知外部漂移。本仓库沿用外部架构/发布手册并新增环境与维护页作为实际应用。

### 交付与知识状态

技能提供开发知识的写法与检查工具，不组织产品审批。持续维护、持续同步与强制门按项目实际接入分别说明；没有PRD也可以交付准确实现知识。源码行为、测试执行和运行观察按实际证据范围表达，不能将脚本存在写成已部署。

mapping和单页包只读路径及所选知识页，不读源码内容。工具直接列coverageSummary/coverageMessage及覆盖、缺口、部分覆盖、歧义、知识引用与未解析候选；执行者自行读代码核实，普通维护不填逐段记录。知识写法、证据边界及必要技术缺口统一见正文核对方法。

### 正文与来源的核对

重要实现结论沿实际调用链追源，核对入口、配置覆盖、生效条件和异常，不扩大平台或渠道范围。对错误直接改原句/表格/步骤，读回相关正文并检查重复位置；来源进入实际所属模块，导航和运行时路径不机械当依赖。复审关注是否忠于代码、遗漏条件和知识是否清楚，不要求凑问题或逐句复述实现。

### 待确认项的语义准入

待确认项只列合理查证后仍影响开发理解、修改或本次操作的技术问题，并交代影响、已有依据与下一步查证。已知边界、未执行验证、临时会话状态和未被要求的未来能力分别归位；没有符合项就明确写无。未演练恢复等风险仍保留在操作旁，不能为减少问题而删掉。模板保留章节，脚本不按关键词判断语义。
